## 运行冒烟测试

前置条件：

- 后端已启动并可访问 `GET /api/health`（默认端口 8771）；
- 已安装 Microsoft Edge；
- 已安装 `websockets`（项目 `.venv` 已包含）。

命令：

```powershell
cd ~/multi_xuanwo
.\.venv\Scripts\python.exe scripts\v2_smoke.py --port 8771
```

常用参数：

```powershell
# 指定完整 URL / 超时 / 截图目录
.\.venv\Scripts\python.exe scripts\v2_smoke.py `
  --url http://127.0.0.1:8771/ `
  --timeout 25 `
  --out-dir .e2e\ui-v2
```

脚本行为：

- 使用临时 profile 启动 `msedge --headless=new`，自动选择空闲调试端口；
- 订阅 `Runtime.exceptionThrown`、`Runtime.consoleAPICalled`（error/assert）与 `Log.entryAdded`；
- 等待 `.app` / `.welcome` 出现，并做一次网络空闲近似等待；
- 按文字点击侧栏（概览/任务/运行/文件/审阅/记忆/Agent/设置），断言主标题变化、侧栏高亮、无新增未捕获异常；
- 打开「新建任务」对话框，断言 textarea 获得焦点、Escape 关闭；
- Ctrl+K 打开命令面板，输入 `task`，Escape 关闭；
- 每个视图截图 1440x900，保存到 `.e2e/ui-v2/<view>.png`；
- 输出 PASS/FAIL 摘要；硬失败时退出码为 1。Edge 在 `finally` 中结束。

### 已确认缺陷

> 注：该行为已在后续轮次变更，见 DEFECTS-V2。

1. **新建任务对话框未聚焦输入框**（阻断键盘优先流程）
   - 位置：`新建任务` 对话框。
   - 现象：打开后 `document.activeElement` 是右上角「关闭」按钮
     （`button.btn.btn-icon`），不是 textarea。
   - 预期：textarea 应获得焦点，用户可直接输入。
   - 疑似原因：对话框 `useFocusTrap` 在挂载后把焦点移到第一个可聚焦元素
     （关闭按钮），覆盖了 textarea 的 `autoFocus`。
   - 复现：运行冒烟脚本，查看 `[new-task] textarea 自动获得焦点` 一项。
   - 状态：仅记录，未修改应用源码。

### 其他观察（未作为硬失败）

- `GET /api/config/files/policy` 返回 **405 Method Not Allowed**，由
  `Network`/`Log` 以网络错误记录。页面未崩溃，但后端未提供该读取路由。
- 「记忆」视图目前只有标题，页面主体为空（疑似占位实现）。
- 「运行记录」页在调度空闲时仍显示红色「停止」按钮（`disabled`），
  状态栏同时显示「调度空闲」，视觉语义略有冲突。
- 概览「最近活动」中存在历史脏数据（标题显示为 `??????`），属于数据问题而非渲染异常。
- 冒烟测试只验证结构、交互与异常，不验证业务数据正确性。
